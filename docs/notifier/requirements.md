# 要件：通知Bot

## 受信

- Discord Gateway v10 に1本だけ接続する（シャーディングしない。Bot が入るサーバーは少数の前提）。
- 切断・ゾンビ接続（ハートビートの ACK が来ない）・Reconnect（op 7）・Invalid Session（op 9）から自動で戻る。Resume できるときは Resume して取りこぼしを避ける。
- 再接続は1秒から倍々で最大60秒（±20%のジッター）。Reconnect・ゾンビ接続・Invalid Session もこのバックオフに従う（Invalid Session は最低1〜5秒）。バックオフの回数は、つながってから60秒続いたときに戻す。
- Resume が3回続けて失敗したら、セッションを捨てて Identify からやり直す。
- 1日の Identify 上限を使い切っていたら回復まで待つ。
- 設定を直さないと戻らないエラー（4004 トークン不正、4013/4014 intents、`/gateway/bot` の401など）では接続をやめ、Duet に一度知らせる。

## 振り分け

- 通常の投稿と返信（type 0 と 19）だけを扱う。DM は扱わない。
- 自分（`TARGET_USER_ID`）の投稿と、この Bot 自身の投稿は知らせない。
- メンション・返信・ロールのメンション・Bot へのメンション・キーワードは判定モデルを通さずに知らせる。
- それ以外は判定モデルが「関係あり」としたときだけ知らせる。判定モデルを設定していない（`DECISION_PROVIDER=none`、既定）ときは、判定せずにそのまま知らせる（自分の投稿も含む。この Bot の投稿は除く）。
- 判定は見逃しを避ける側に寄せる（余計な通知は Duet が返事をしないことで流せる）。判定モデルには「迷ったら関係あり」と指示する。Clef では確率か重要度のどちらかがしきい値以上なら知らせる。
- 判定モデルの呼び出しに失敗したら（エラー、時間切れ、使用量の上限、読めない応答）、投稿を捨てずに、判定できなかったことと理由を添えて知らせる。
- 判定モデルは `DECISION_PROVIDER` で選べる（既定は `none`＝判定しない。`clef`・`openrouter`・`openai-compatible`・`anthropic`）。Clef（Cloudflare Workers AI）はデータを残さない。OpenRouter は、学習に使わないエンドポイント（ZDR か、不正利用の監視のための保持だけのもの）だけに送るのを既定にする。
- 判定モデルには、投稿の中の指示に従わないよう指示し、投稿は区切りの内側に入れて渡す。サーバー名・チャンネル名も区切りの内側に入れる。名前や本文から、ほかの投稿の行や本人の印をまねられないようにする（印は行頭にだけ付け、本人の印は user_id で決める）。
- 通知対象の人が見られないチャンネルの投稿は知らせない（メンションでも）。非公開スレッドは、親チャンネルを見られて、スレッドに参加している（またはスレッドの管理の権限がある）ときだけ見られるとみなす。ただし通知対象の人へのメンションは、その人をスレッドに加えるので、親チャンネルを見られれば知らせる。スレッドに加えられた・外されたことは、そのスレッドのシステムメッセージと本人の投稿からすぐに反映する。通知対象の人がサーバーにいなければ知らせない。判断の材料が揃わないときは知らせる。

## 送信

- duet-send を外部プロセスとして起動し、本文は標準入力で渡す（引数の長さ・クォートの問題を避ける）。
- 送信の最短間隔を守り、その間の通知は1通あたり `MAX_MESSAGE_CHARS`（7000文字）以下にまとめる（duet-send の上限8000文字、タグ込みに余裕を見る）。失敗した通知は残して再送する。未送信は送信中の分を除いて最大50件で、送信の成否にかかわらず、超えた分は古いものから捨てる。
- 宛先を `DUET_ROUTES`（サーバーID・チャンネルIDごと）で振り分けられる。優先順位はチャンネル → スレッドの親チャンネル → サーバー → 既定の宛先。宛先が違う通知は1通にまとめず、宛先ごとに最短間隔・再送・未送信の上限（50件）を守る。この Bot 自身のお知らせは既定の宛先に送る。未設定なら全部を既定の宛先に送る。
- 宛先名は空白・カンマ・`=` を含めず、`-` で始めない（フラグに見えないように）。同じ ID の重複はエラー。
- `DUET_ROUTES` の ID は、サーバーID・チャンネルID・スレッドの親チャンネルIDのどれか（カテゴリのIDは一致しない）。duet-send の既定の宛先の名前は書かない（載っていないサーバーは元から既定へ行き、書くと同じセッション向けのキューが2つできる）。
- 宛先つきのキューが3回続けて送信に失敗したら、既定の宛先にその宛先名と最後のエラー（200文字まで）を1回だけ知らせる。成功すると数え直し、また3回続けて失敗したら知らせる。失敗した通知そのものは移さず、そのキューで再送を続ける。既定の宛先のキュー自身は知らせない。
- duet-send には、この Bot のトークンと判定モデルの API キー（`CLOUDFLARE_AI_TOKEN` を含む）を渡さない。
- duet-send が時間内（2分）に終わらなければ、子プロセスごと止めて失敗にする。
- 通知文では、他人が書いた文字列（名前・本文・判定の理由）を区切りの内側だけに置く。区切りの外は ID とリンクだけ。

## 運用

- 設定は `.env` だけ。起動時に値を検査し、どの項目が悪いかを示して止まる（値そのものは表示しない）。
- `--check` で、トークン・Message Content Intent・参加サーバー・通知対象の人の参加・duet-send（`DUET_ROUTES` の宛先ごとの dry run を含む）・判定モデルを確かめられる。
- 二重起動を防ぐ。SIGINT / SIGTERM で Gateway を閉じ、溜まった通知を送ってから終わる（最大60秒。過ぎても送信中の duet-send は子プロセスごと強制的に止める）。
- macOS・Linux・Windows で、OS の起動（ログイン）時に自動で起動し、落ちたら起動し直す。
