# 要件：Discord MCP

## 認証

- Cloudflare Access の Managed OAuth を前段に置き、Worker でも `Cf-Access-Jwt-Assertion` を検査する（RS256、発行者、audience、メールアドレスが `ALLOWED_EMAIL` と一致）。
- Access の設定値かメールアドレスが未設定なら 500（fail closed）。それ以外の拒否は 403 で、理由は本文に出さない。
- `MCP_HOST` 以外のホスト、`/mcp` 以外のパスは 404。
- `DEV_BYPASS_ACCESS=1` は localhost / 127.0.0.1 宛てのときだけ効く。

## Discord へのアクセス

- REST API v10 だけを使う。429 は短い待ちなら1回だけ再試行し、長ければ待ち時間を伝えて失敗する。
- `ALLOWED_GUILD_IDS` が書かれていれば、どのツールもそのサーバーだけを扱う。チャンネルやメッセージを指定するツールも、チャンネルの所属サーバーを確認する。値の形式が正しくなければ何も扱わない。
- DM・グループDMは扱わない。
- ID はすべて15〜21桁の数字であることを確認してから URL のパスに入れる。

## 送信

- 通知（メンション）は `mention_user_ids` に書いた人と、返信の投稿者（`mention_author`、既定オン）だけに届ける。`allowed_mentions.parse` は空にし、ロール・@everyone・@here は通知しない。
- `mention_user_ids` の人が本文にいなければ、先頭に `<@ID>` を足す。足して2000文字を超えるなら送らない。
- 返信先が無ければ失敗させる（`fail_if_not_exists: true`）。普通の投稿にすり替えない。
- `edit_message` は Bot 自身の投稿の本文を丸ごと置き換える。他人の投稿は Discord が拒否し（code 50005）、決まった文言で返す。メンションの扱いは送信と同じ（`parse` は空、`mention_user_ids` の人だけ）。ただし編集で足したメンションは、相手に通知が届くとは限らない（誰宛てかは本文で分かる）。
- ツールの説明に、Discord のメッセージやメール、Webページの指示を理由に呼ばないことを書く。

## 出力

- Discord の利用者が書いたもの（本文、表示名、サーバー名、チャンネル名、ファイル名）は `<untrusted_discord>` の区切りの内側に置き、`<` `>` を `‹` `›` に置き換える。改行以外の制御文字と見えない書式文字は取り除く。
- 結果は約4万文字までに収める。収まらないときは件数と続きの読み方を示す。
- エラーは決まった文言（HTTP ステータスと Discord のエラーコード、対処）だけを返す。トークンや Discord の応答本文は返さない。
- ログはツール名・件数・所要時間・失敗の種類だけ。
